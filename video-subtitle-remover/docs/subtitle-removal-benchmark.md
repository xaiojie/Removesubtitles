# 竖屏视频硬字幕去除实测总结

测试日期为 2026 年 11 月 18 日。

五段素材中，**裁出字幕带，用 PP-OCRv5 Mobile 定位，再用 GPU LaMa 逐句修复**取得了较好的速度和画面效果。推荐方案整批实测 **196.162 秒**，包含共享模型初始化和五段成片写出。仓库的固定框 STTN 为每段启动独立进程，五段合计 **300.425 秒**。在这两种实测运行方式下，推荐方案用时减少 **34.7%**。

推荐方案的 741 个抽检帧中，OCR 残留命中为 0，抽检范围包含字幕切换点。同帧对照检查了细体中文、粗描边中文和双行英文。视频 5 的绳索附近仍有轻微软化。

## 测试条件

- 五段完整竖屏 MP4 均为 720×1280、30 fps，视频共 2,292 帧，合计 76.4 秒。视频 1 的字幕带中途换位，视频 4 包含双行英文。
- 测试机为 Windows、Intel Core i5-14450HX、NVIDIA GeForce RTX 5050 Laptop GPU（约 8 GiB 显存）。运行环境为 Python 3.11.9 和 PyTorch `2.7.0+cu128`。
- 原生模式使用基于 `d95f4f4` 的本地工作区，包含 Windows 非 ASCII 路径的模型加载兼容改动。裁字幕带的实验流程在独立脚本中运行，复用项目的模型权重和 LaMa 实现。 [原生命令行入口](../backend/main.py) · [LaMa 实现](../backend/inpaint/lama_inpaint.py)

## 推荐流程与参数

1. 按原始分辨率框出字幕可能出现的带状区域。字幕位置变化时覆盖各个高度。将带状裁切图送入 PP-OCRv5 Mobile，测试设置为 CPU 3 线程、最长边上限 720 像素。将检测框换回原画坐标。
2. 每 6 帧检测一次。相邻采样结果有变化时，对中间帧补检，并将连续的相近文字框合并成字幕区间。与每 3 帧检测的版本相比，这五段中进入修复的帧集合分别相同，检测调用从 910 次降到 743 次。
3. 每个文字框向外扩 5 像素作为修复遮罩，遮罩四周保留 28 像素的上下文裁块。GPU LaMa 每批最多修复 4 帧，将遮罩内的像素合回原帧。
4. FFmpeg 使用 `libx264`、`preset=fast`、`CRF=18` 写出视频，原 AAC 音轨直接封装。批量处理时复用同一进程里的检测和修复模型。

这些数值对应本机的实测配置。换素材时按字幕的实际位置调整检测带，优先抽查换行、换位和复杂背景上的短字幕。
